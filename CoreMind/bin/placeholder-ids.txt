# Ids that may stand where an account id would: `check-names.sh literals` accepts these (and generic words such as
# guest or user) as the value of owner/partner/createdBy/user/username/..., in partners/members/KEEP lists, as users-map
# keys, in by=, in records-<id>.json and in <id>@example.com. Anything else there is a finding.
#
# One entry per line:   handle  # what it stands for and where it is used   (one line, at least three words)
# Scoped entry:         handle @ glob glob  # why   (valid only in paths matching a glob; * also crosses /)
# Lowercase handle, no trailing number (guest2 is checked as guest). Trailing digits and . _ - joins of registered
# or generic words are accepted without an entry (guest2, no-reply, evil-guest).
#
# Register a handle only when it is a throwaway fixture or a role, never a person: no owner, partner, household
# member or other real account id, and no nickname or spelling of one. Prefer the first block (alex, sam, ana, ...)
# for a new fixture person. With the local needle list, `literals` and `tree` fail when an entry here is or contains a
# needle, so a real id cannot be registered; the untracked needle lists, not this file, say who is real. A malformed
# line (no reason, uppercase, duplicate) makes `check-names.sh` exit 2.
#
